# 403 登录重试实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 规则接口返回 403 时显示登录弹窗，登录接口回写 Cookie 后重试原请求，并支持失败重试、取消和并发 403 合并。

**Architecture:** 在 `frontend/rules.js` 中新增可复用登录弹窗控制器和 `authenticatedFetch`。登录请求使用原始 `fetchImpl`，规则读取与保存统一通过认证包装器；每次凭据提交只重试原请求一次，403 时回到同一弹窗等待下一次提交。

**Tech Stack:** 原生 JavaScript、HTML/CSS、Fetch API、URLSearchParams、Node.js 内置 `node:test`、现有最小 DOM 替身。

## 全局约束

- 登录接口固定为 `/api/v2/auth/login`。
- 登录与规则请求均使用 `credentials: 'include'`。
- 不硬编码、预填、保存或记录 `frontend/登录.txt` 中的凭据。
- 不修改规则生成、Pure 动态排除、安全分阶段保存和失败恢复逻辑。
- 不引入第三方依赖，不自动 Commit 或 Push。

- [x] **步骤 4：实现共享登录尝试**

使用模块级弹窗和当前尝试状态：

```js
let loginDialogElements = null;
let loginAttempt = null;

const requestLogin = (fetchImpl = fetch) => {
  if (loginAttempt) {
    return loginAttempt.promise;
  }

  let resolveAttempt;
  let rejectAttempt;
  const promise = new Promise((resolve, reject) => {
    resolveAttempt = resolve;
    rejectAttempt = reject;
  });
  loginAttempt = { promise, resolve: resolveAttempt, reject: rejectAttempt, fetchImpl };
  showLoginDialog();
  return loginAttempt.promise;
};
```

表单提交直接调用原始 `fetchImpl`：

```js
await fetchImpl('/api/v2/auth/login', {
  method: 'POST',
  credentials: 'include',
  body: new URLSearchParams({ username, password })
});
```

登录响应非成功或网络错误时不结束 Promise，只显示错误并允许重试；成功状态结束本次尝试 Promise，但弹窗保持“正在验证”状态。

成功提交时必须先保存当前尝试引用、将 `loginAttempt` 置空，再调用该引用的 `resolve()`。这样原请求重试仍为 403 时，下一轮 `requestLogin` 会创建新的待处理 Promise，而不会复用已完成 Promise 形成自动循环。取消时同样先清理模块状态，再调用当前尝试的 `reject(new Error('已取消登录'))`。

- [x] **步骤 5：实现用户驱动的单次重试循环**

实现：

```js
const authenticatedFetch = async (url, options = {}, fetchImpl = fetch) => {
  let response = await fetchImpl(url, options);
  while (response.status === 403) {
    await requestLogin(fetchImpl);
    response = await fetchImpl(url, options);
    if (response.status === 403) {
      showLoginError('用户名或密码错误，请重试');
    }
  }
  closeLoginDialog();
  return response;
};
```

循环只由用户再次提交凭据推进，不自动重复发送请求。取消按钮拒绝共享 Promise，并用“已取消登录”结束所有等待请求。
