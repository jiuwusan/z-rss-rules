# 403 登录重试设计

## 1. 目标

规则读取或保存接口返回 HTTP 403 时，在当前页面弹出登录窗口，收集用户名和密码并调用登录接口。登录接口回写 Cookie 后，自动重试原请求，使用户无需刷新页面或手动重新执行操作。

## 2. 范围

- 覆盖 `/api/v2/rss/rules` 和 `/api/v2/rss/setRule` 请求。
- 登录接口固定为 `/api/v2/auth/login`。
- 不修改现有规则生成、Pure 动态排除、安全分阶段保存和失败恢复逻辑。
- 不保存、硬编码、预填或记录 `frontend/登录.txt` 中的账号密码。
- 不增加第三方依赖，不新增独立登录页面。

## 3. 页面交互

页面内创建模态登录窗口，包含：

- 用户名输入框。
- 密码输入框，使用密码类型隐藏内容。
- “登录”按钮。
- “取消”按钮。
- 登录错误提示区域。

首次出现 403 时打开弹窗并聚焦用户名输入框。提交期间禁用输入框和按钮，避免重复登录请求。

登录接口失败、返回非成功状态，或登录后原请求仍返回 403 时，弹窗保持打开并显示“用户名或密码错误，请重试”。密码输入框清空并重新聚焦，用户名保留便于修正。

用户取消登录后关闭弹窗，所有等待认证的请求以“已取消登录”失败，页面沿用现有加载或保存错误展示逻辑。

## 4. 请求架构

新增统一认证请求函数：

```js
authenticatedFetch(url, options, fetchImpl): Promise<Response>
```

处理流程：

1. 使用传入的 `fetchImpl` 执行原请求。
2. 非 403 响应直接返回。
3. 403 响应调用共享登录尝试 `requestLogin(fetchImpl)`。
4. 登录接口成功后，弹窗进入“正在验证”状态但暂不关闭；使用相同 URL 和请求参数重试原请求一次。
5. 重试不再返回 403 时关闭弹窗并返回响应。
6. 重试仍为 403 时，在同一个弹窗中显示错误并创建下一次共享登录尝试；每次凭据提交只触发一次原请求重试，不在后台自动循环。

`requestRules` 和 `setRule` 改用 `authenticatedFetch`，并继续为原请求设置 `credentials: 'include'`。

登录请求直接使用原始 `fetchImpl`，不经过 `authenticatedFetch`，防止登录接口自身 403 导致递归。

## 5. 登录请求

登录请求使用 URL 编码表单：

```text
POST /api/v2/auth/login
credentials: include
body: username=<用户名>&password=<密码>
```

响应为成功状态时，视为 Cookie 已由浏览器接收，并立即重试等待中的原请求。响应为非成功状态时在弹窗内显示登录错误。

最终认证是否成功以重试原请求不再返回 403 为准，从而兼容登录接口成功响应正文格式差异。

## 6. 并发控制

使用模块级共享登录尝试 Promise 和可复用弹窗：

- 没有登录尝试时，第一个 403 创建或显示弹窗，并创建本次登录尝试 Promise。
- 登录尝试进行中时，后续 403 复用同一个 Promise，不重复创建弹窗或发送登录请求。
- 登录接口成功后结束本次尝试 Promise，等待请求分别重试；弹窗保持“正在验证”状态。
- 所有正常场景下，同一 Cookie 会使等待请求得到一致的认证结果；任一重试仍为 403 时，弹窗恢复输入状态并创建下一次共享尝试。
- 重试成功或用户取消后关闭弹窗并清理当前尝试状态，允许后续 403 再次启动登录流程。
- 登录成功版本号用于识别 Cookie 更新前已发出、更新后才返回的旧 403；这类响应静默重试一次，不重复弹窗。
- 取消版本号用于标记整个认证批次；同批仍在途的迟到 403 直接以“已取消登录”结束，不重新打开弹窗。
- 某请求重试成功时，若另一个请求已经进入下一轮登录，成功请求不得关闭仍被使用的弹窗。

一次登录成功后，每个等待请求分别重试自己的原请求。

## 7. 错误处理

- 原请求非 403 错误：保持现有 HTTP 错误处理。
- 登录接口网络错误或非成功状态：弹窗保持打开并显示错误，允许继续重试。
- 登录后原请求仍为 403：判定凭据无效，弹窗保持打开，等待重新提交。
- 用户取消：抛出明确的“已取消登录”错误。
- 登录过程中不输出用户名或密码到控制台。

## 8. 可访问性

- 弹窗使用 `role="dialog"`、`aria-modal="true"` 和标题关联。
- 弹窗显示期间将规则页面设为 `inert`，阻止键盘焦点进入背景控件；关闭后恢复。
- 用户名和密码输入框均有可见标签。
- 错误提示使用 `role="alert"`。
- Enter 可提交登录表单，Escape 或“取消”按钮关闭弹窗。
- 弹窗打开后设置初始焦点，关闭后恢复到触发认证前的焦点元素（仍存在时）。

## 9. 测试

在现有最小 DOM 替身和 Node.js 测试中覆盖：

1. 非 403 请求不打开登录弹窗，也不重试。
2. 规则读取返回 403 后提交登录表单，Cookie 登录请求成功并重试原读取请求。
3. 保存请求返回 403 后登录成功，按原规则定义重试保存请求。
4. 登录请求使用 URL 编码表单和 `credentials: 'include'`。
5. 登录失败时弹窗保留、显示错误并清空密码。
6. 登录后原请求仍返回 403 时不无限重试，等待用户再次提交凭据。
7. 多个并发 403 只显示一个弹窗并共享一次登录。
8. 用户取消后等待请求失败，弹窗关闭。
9. 登录期间控件禁用，凭据不出现在页面状态或日志中。
10. Cookie 更新前发出的请求迟到 403 时静默重试。
11. 并发请求进入不同重试阶段时不互相关闭弹窗，取消后同批迟到响应不重新弹窗。

## 10. 未覆盖范围

- 不实现记住用户名或密码。
- 不主动刷新 Cookie 或检测会话剩余时间。
- 不新增验证码、多因素认证或独立账号管理。
- 不修改服务端 Cookie 属性或跨域策略。
