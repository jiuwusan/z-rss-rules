# Quick Tools 侧边导航与 Torrent 重命名弹窗设计

## 1. 目标

优化 Quick Tools 页面信息层级。桌面端采用左侧功能导航、右侧功能内容的整体结构；Torrent 文件重命名功能以种子列表为主界面，通过每个种子的“重命名”按钮打开弹窗，在弹窗内完成文件加载、正则预览、选择和保存。

本次调整只改变页面布局和 Torrent 重命名交互入口，不修改 qBittorrent API、鉴权方式、RSS 规则数据结构及文件重命名算法。

## 2. 页面整体结构

- 页面顶部保留标题“qBittorrent Quick Tools”和现有说明。
- 标题下方使用左右布局：
  - 左侧为固定宽度的纵向功能导航，包含“RSS 规则关键词”和“Torrent 文件重命名”。
  - 右侧为内容区域，仅展示当前选中功能的完整内容。
- 当前功能使用现有蓝色主题高亮，并保留 `tablist`、`tab`、`tabpanel` 语义及键盘焦点样式。
- 继续按首次选择懒加载对应工具；功能往返切换时不重复初始化，并保留已初始化内容的页面状态。

## 3. RSS 规则功能

- 右侧内容区直接展示现有 RSS 规则卡片列表和保存操作。
- 关键词标签编辑器、纯净规则样式、保存状态和错误提示保持现有行为。
- 宽屏下规则卡片继续使用双列排列；内容区域不足或进入窄屏时改为单列。

## 4. Torrent 种子列表主界面

Torrent 功能的常驻内容只展示种子浏览与入口操作，不再同时常驻文件重命名编辑器。

- 顶部工具栏包含搜索框和“刷新 Torrent”按钮。
- 下方展示按接口既有顺序返回的 Torrent 种子列表。
- 每个种子项展示名称、hash 和“重命名”按钮。
- 搜索继续按名称或 hash 忽略大小写过滤。
- 点击种子名称或列表空白区域不请求文件；只有点击“重命名”按钮才进入文件重命名流程。
- Torrent 列表加载、失败和刷新状态继续显示在当前功能内容区。
- 加载或保存等禁止重复操作的阶段，相应按钮保持禁用。

## 5. 重命名弹窗

### 5.1 打开与关闭

- 点击某个种子的“重命名”按钮后打开大尺寸模态弹窗。
- 弹窗标题展示当前种子名称，辅助信息展示 hash，便于用户确认操作对象。
- 弹窗打开后调用现有文件列表接口加载当前种子的文件。
- 文件加载期间保留弹窗骨架，禁用正则输入和保存相关操作，并显示加载状态。
- 用户可通过“关闭”按钮、右上角关闭按钮或 `Escape` 关闭弹窗；保存进行中禁止关闭，避免用户误认为请求已经取消。
- 关闭弹窗后清理当前种子、文件、预览、输入值和错误状态，同时递增请求版本，使旧响应无法写入后续弹窗。
- 模态弹窗打开时设置正确的对话框语义，初始焦点进入弹窗；关闭后焦点返回触发该弹窗的“重命名”按钮。

### 5.2 编辑与预览

- 弹窗上方提供 `matchRegex`、`replaceRegex` 和 flags 输入框。
- 文件加载完成且匹配正则为空时，展示全部原始文件行，状态为“待输入匹配正则”。
- 正则有效时，每个文件按现有规则生成相邻的“原始文件”和“替换预览”两行。
- 正则无效时保留原始文件行，不生成替换预览行，并显示明确错误。
- 未匹配、无变化、无效文件名和目标路径冲突的预览继续显示，但不可选择保存。
- 输入正则只重建本地预览，不重复请求文件接口。

### 5.3 弹窗操作

- 弹窗操作区提供“全选”“取消全选”“刷新文件”“保存重命名”和“关闭”。
- 全选和取消全选只操作有效的替换预览项。
- 保存继续串行调用现有重命名接口，遇到失败时停止后续保存并显示错误。
- 保存成功后保持弹窗打开，并重新请求当前种子的文件列表，以服务端最新结果重建原始行和预览。
- 刷新文件只更新当前弹窗中的文件列表，不刷新主页面 Torrent 列表。

## 6. 状态与数据流

1. 用户进入 Torrent 功能，工具按现有机制首次初始化并请求 Torrent 列表。
2. 用户搜索或刷新时，只更新主页面的 Torrent 列表状态。
3. 用户点击某一项的“重命名”，记录触发按钮和当前种子，打开弹窗并请求文件列表。
4. 文件返回后，根据当前正则输入构建预览；用户修改输入时只执行本地重建。
5. 用户保存选中项后，沿用现有串行保存流程，再刷新弹窗文件列表。
6. 用户关闭弹窗时失效未完成的文件请求并清理弹窗状态，主页面搜索条件和 Torrent 列表保持不变。

Torrent 列表请求和弹窗文件请求继续使用独立的版本号，避免刷新列表、快速切换种子或关闭后重新打开时发生竞态覆盖。

## 7. 响应式布局

- 桌面端页面主体使用固定侧边导航和自适应内容区。
- 内容宽度不足时，RSS 卡片列表退化为单列。
- 小于现有移动端断点时，功能导航移动到内容上方并改为横向或纵向按钮组，内容区占满宽度。
- Torrent 种子列表和文件预览表格在列宽不足时允许横向滚动，避免压缩名称和 hash 到不可读。
- 重命名弹窗在窄屏使用接近全屏的尺寸，内容区独立滚动，操作按钮允许换行排列。

## 8. 可访问性与错误处理

- 保留功能导航的 tab 语义、选中状态和面板关联关系。
- 重命名入口使用真实按钮，并提供能关联到种子名称的可访问名称。
- 弹窗使用 `role="dialog"`、`aria-modal="true"` 和标题关联。
- 打开弹窗后限制键盘焦点停留在弹窗内；关闭后恢复到触发按钮。
- Torrent 列表加载失败、文件加载失败、正则错误和保存失败分别显示，不互相覆盖为错误的成功状态。
- 文件请求失败后保留弹窗和重试入口，不展示过期文件预览。

## 9. 测试范围

- 页面 HTML 提供左侧功能导航和右侧内容区域结构。
- 桌面端使用左右布局，窄屏下导航移动到内容上方。
- 功能切换仍只初始化一次并保留状态。
- Torrent 初始化后主界面只展示种子列表，不常驻文件编辑器。
- 搜索、刷新和加载错误行为保持正常。
- 每个 Torrent 项展示“重命名”按钮，点击其他区域不请求文件。
- 点击“重命名”打开正确种子的弹窗并请求对应文件。
- 弹窗加载、输入、原始行、预览行、选择、刷新和保存行为覆盖现有测试语义。
- 关闭弹窗清理状态、失效旧请求并恢复触发按钮焦点。
- 保存期间禁止关闭，保存成功后弹窗保持打开并刷新文件。
- 现有鉴权、API、RSS 规则及正则替换单元测试继续通过。

## 10. 最小影响范围

预计主要修改以下文件：

- `frontend/quick-tools.html`：增加页面左右布局容器语义。
- `frontend/quick-tools.css`：实现侧边导航、右侧内容、种子列表主界面、模态弹窗及响应式样式。
- `frontend/torrent-renamer.js`：将常驻编辑器改为按种子打开的弹窗，并管理弹窗生命周期与焦点。
- `tests/quick-tools.test.js`：验证整体布局结构和功能切换。
- `tests/torrent-renamer.test.js`：验证种子入口、弹窗流程、竞态、关闭和保存行为。

`frontend/auth.js`、`frontend/qbittorrent-api.js`、`frontend/rss-rules.js` 及其业务逻辑不在修改范围内。

## 11. 未覆盖风险

- Fake DOM 对真实浏览器的焦点陷阱、`Escape`、滚动锁定和表格横向滚动验证有限，需要真实浏览器补充检查。
- 大量 Torrent 或单个 Torrent 包含大量文件时，列表渲染性能仍取决于现有全量 DOM 渲染方式，本次不引入虚拟列表。
- 保存请求本身无法由前端真正取消；保存期间通过禁止关闭避免产生状态误解。
