# Torrent 文件原始与预览双行展示设计

## 1. 目标

选中 Torrent 并读取文件成功后，立即展示完整文件列表，使用户可以直接参考文件名称编写 `matchRegex` 和 `replaceRegex`。输入正则后，每个文件使用相邻两行展示原始路径和替换后预览路径。

## 2. 行展示规则

- 未选中 Torrent：表格为空，状态显示“请选择 Torrent”。
- 文件加载中：保留当前加载状态，不展示尚未返回的文件。
- 文件加载成功且 `matchRegex` 为空：每个文件只显示一条“原始文件”行，文件内容使用 qBittorrent 返回的完整相对路径；状态显示“待输入匹配正则”。
- `matchRegex` 无法编译：继续保留全部“原始文件”行，不生成预览行；页面显示正则错误。
- `matchRegex` 有效：每个文件先显示“原始文件”行，紧接一条“替换预览”行。预览行显示完整 `newPath` 和现有校验状态。
- 未匹配、无变化、无效名称或目标冲突的文件也显示预览行，但保存选择框禁用。

## 3. 保存选择

- 原始文件行只读，不显示保存选择框。
- 替换预览行显示保存选择框。
- 只有 `isValid` 的预览行默认勾选并允许切换。
- 全选、取消全选和保存逻辑继续只操作预览项，不操作原始行。

## 4. 表格结构与样式

表头调整为“保存、类型、文件名称、状态”：

- 原始行：保存列为空，类型为“原始文件”，文件名称为 `oldPath`。
- 预览行：保存列为复选框，类型为“替换预览”，文件名称为 `newPath`，状态沿用现有预览状态。

同一文件的两行使用相邻样式和分组边框。原始行保持中性背景，预览行使用轻微强调背景，长路径允许换行或横向滚动。

## 5. 状态与兼容性

- 文件请求失败、Torrent 列表刷新失败、保存忙碌和异步请求版本保护逻辑保持不变。
- `buildRenamePreview` 的正则、路径、冲突和选择语义保持不变。
- 输入正则时只重建表格行，不重新请求文件。
- RSS 工具、鉴权和 qBittorrent API 模块不变。

## 6. 测试范围

- 选中 Torrent 后、正则为空时立即按文件顺序显示全部原始路径。
- 正则有效时，每个文件生成相邻的原始行和预览行。
- 保存选择框只出现在预览行，且有效项默认勾选。
- 未匹配或冲突项仍生成预览行但不可保存。
- 无效正则时保留原始文件行并显示错误。
- 刷新文件后以最新服务端文件列表重建原始行和预览行。
- 现有串行保存、失败停止、刷新和竞态测试继续通过。

## 7. 未覆盖风险

- Fake DOM 不验证真实浏览器表格布局、长路径换行和视觉分组效果。
- 仍需在真实 qBittorrent 5.0 数据上确认超长路径及大量文件时的可读性和性能。
