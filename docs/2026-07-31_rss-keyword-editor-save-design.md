# RSS 关键词编辑与安全保存设计

## 1. 目标

在现有 RSS 规则展示页上增加关键词编辑和“保存全部”能力。页面从 qBittorrent 读取完整规则定义，只动态修改每类规则允许变化的字段，并通过 `POST /api/v2/rss/setRule` 回写。

## 2. 规则分类

- Pure 规则使用精确名称 `Pure-HDSWEB` 识别。
- 除 `Pure-HDSWEB` 外，其余返回规则均视为普通压制组规则。
- Pure 规则的 `mustContain` 和普通规则的 `mustNotContain` 始终保留接口返回值。

## 3. 关键词草稿

- 普通规则提供关键词输入框，支持中文逗号、英文逗号和换行分隔。
- 输入值去除首尾空白、空项和重复项，保留首次出现顺序。
- Pure 规则不提供输入框，显示“关键词由其他规则自动维护”。
- 页面只在浏览器内存中保存草稿，不使用本地存储。
- 任一普通规则草稿与服务端关键词不同，页面显示“有未保存修改”。

## 4. 字段生成

### 4.1 普通规则

- `mustContain` 取接口返回值第一个 `(` 之前的内容作为固定前缀。
- 将草稿关键词用 `|` 连接后拼接为括号部分。
- 草稿为空时使用 `九五三` 作为唯一补位关键词。
- `mustNotContain` 和其他规则字段原样保留。

### 4.2 Pure 规则

- `mustContain` 和其他非动态字段原样保留。
- 首次读取时，将所有普通规则当前关键词从 Pure 当前 `mustNotContain` 关键词中扣除，剩余内容作为 Pure 固定排除项。
- 最终 `mustNotContain` 为“Pure 固定排除项 + 所有普通规则最终关键词”的去重合集。
- 普通规则空草稿生成的补位关键词 `九五三` 也进入 Pure 动态排除合集。

## 5. 安全分阶段保存

qBittorrent RSS API 不提供批量事务。为避免保存期间同一标题短暂同时被 Pure 和普通规则匹配，保存顺序如下：

1. 计算旧普通关键词合集和新普通关键词合集。
2. Pure 安全排除列表使用“固定排除项 + 新关键词 + 仅旧关键词”。集合仍覆盖全部新旧关键词，并让纯新增场景的安全值直接等于最终值，避免重复写入 Pure。如果与当前 Pure 定义不同，先写入临时 Pure 定义。
3. 依次写入 `mustContain` 发生变化的普通规则。
4. Pure 最终排除列表使用“固定排除项 + 新关键词”。如果与上一步服务端预期值不同，再写入最终 Pure 定义。
5. 全部成功后重新调用 `GET /api/v2/rss/rules`，以服务端真实数据重建页面。

保存只提交动态字段实际变化产生的必要请求。每次 `setRule` 均提交完整 `ruleDef`，未指定为动态的字段保持读取值。

## 6. API 请求

- 读取：`GET /api/v2/rss/rules`。
- 保存：`POST /api/v2/rss/setRule`。
- 保存请求体使用 `URLSearchParams`，字段为 `ruleName` 和 JSON 序列化的 `ruleDef`。
- 所有请求设置 `credentials: "include"`。
- HTTP 非成功状态转换为包含操作和规则名的异常。

## 7. 页面状态与错误处理

- 加载期间显示“正在加载规则”。
- 保存期间禁用所有输入框和保存按钮，按钮显示“保存中”。
- 没有修改时禁用保存按钮。
- Pure 规则缺失时允许查看普通规则，但禁用保存并显示明确原因。
- 任一步骤失败时停止后续写操作，显示失败信息，并尝试重新读取服务端规则。
- 保存开始前保留可信的 Pure 固定排除项；失败重读过渡状态时沿用该基线，避免临时安全关键词被误判为永久固定项。
- 普通规则没有变化但 Pure 动态排除项与实际普通关键词不一致时，仍生成 Pure-only 修复操作，允许再次点击“保存全部”完成清理。
- 失败后的页面以重新读取结果为准，不假装已回滚或全部成功。

## 8. 测试范围

使用 Node.js 内置 `node:test` 和现有最小 DOM 替身，不增加依赖。覆盖：

1. 输入分隔、清理和去重。
2. 普通规则动态生成 `mustContain`，空草稿使用 `九五三`。
3. 普通规则 `mustNotContain` 保持不变。
4. Pure 固定排除项提取及最终 `mustNotContain` 生成。
5. 安全保存计划在新增、删除、混合修改下的操作顺序。
6. `setRule` 的 URL、方法、凭据和表单参数。
7. 页面草稿、保存按钮状态以及 Pure 只读提示。
8. 保存成功后重新读取，保存失败后停止并重新读取。

## 9. 范围限制

- 本次不实现登录表单、规则新增删除、规则重命名和本地持久化。
- 不修改 `frontend/rulesArray.txt` 和 `frontend/示例.txt`。
- 不自动提交或 Push Git 变更。
