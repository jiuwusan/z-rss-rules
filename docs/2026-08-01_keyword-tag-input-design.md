# 关键词标签输入设计

## 1. 目标

将普通规则的多行文本输入框替换为标签式关键词编辑器，使关键词边界、删除操作和去重结果更直观。Pure 规则保持只读，不改变现有规则生成与安全保存流程。

## 2. 页面结构

每条普通规则使用一个标签输入容器，包含：

- 已提交关键词标签。
- 每个标签内的关键词文本和删除按钮。
- 尾部单行输入框，用于新增关键词。
- 帮助文案：“输入 `|`、`;`、英文逗号、换行或 Enter 创建标签”。

容器点击时聚焦尾部输入框。保存期间标签删除按钮和输入框统一禁用。

## 3. 输入行为

- 分隔符仅包括 `|`、`;`、英文逗号 `,` 和换行。
- Enter 与上述分隔符作用相同，用于提交当前输入。
- 粘贴或输入包含多个分隔符的文本时，一次拆分并创建多个标签。
- 多行粘贴在浏览器清理单行输入框换行前读取剪贴板文本，确保换行仍可作为分隔符。
- 关键词去除首尾空白、空项和重复项，保留首次出现顺序。
- 输入框失去焦点时，提交尚未带分隔符的剩余内容。
- 输入框为空时按 Backspace，删除最后一个标签。
- 删除按钮只删除对应标签。
- 中文逗号和顿号属于关键词正文，不作为分隔符。
- 中文输入法组合期间不响应 Enter、Backspace 或分隔符提交，组合结束后再处理最终文本。

## 4. 草稿与保存

- `state.drafts[ruleName]` 继续使用字符串数组，不保存标签 DOM 或用户分隔符格式。
- 标签新增、删除或 Backspace 操作后立即更新草稿和“有未保存修改”状态。
- 输入框中的余留文字也会启用保存；保存前统一提交所有余留文字，避免点击保存时因 blur 顺序漏存。
- 标签使用独立容器；草稿变化只刷新该容器，输入框与保存按钮不移动，从而保留连续输入和键盘焦点顺序。
- 标签为空时，现有保存逻辑继续用 `九五三` 生成普通规则 `mustContain`。
- 现有 Pure 动态排除、安全分阶段保存和失败恢复逻辑保持不变。

## 5. 可访问性

- 删除按钮提供包含关键词的 `aria-label`，例如“删除关键词 九门”。
- 输入框提供规则名相关的 `aria-label`。
- 标签容器使用可见焦点样式。
- Enter 创建标签时阻止表单默认行为。

## 6. 测试

使用现有 Node.js 最小 DOM 替身扩展键盘与焦点事件测试，覆盖：

1. `|`、`;`、英文逗号、换行和 Enter 创建标签。
2. 中文逗号和顿号不拆分。
3. 批量输入去空和去重。
4. 删除按钮更新草稿。
5. 空输入 Backspace 删除最后一个标签。
6. blur 提交剩余内容。
7. 标签变化启用“保存全部”。
8. 保存期间输入框和删除按钮禁用。
9. 标签刷新后输入框保持焦点，中文输入法组合期间不会误提交。

## 7. 范围限制

- 不引入第三方标签组件或框架。
- 不支持拖拽排序、标签自动补全和本地持久化。
- 不修改规则生成、API 请求和安全保存顺序。
